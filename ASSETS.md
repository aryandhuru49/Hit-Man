# Exit Clause: Free Assets Guide

The game ships as **greybox**: capsule people, box buildings and flat-colour materials, all generated by Editor scripts. This guide shows how to swap in free, good-looking assets, step by step, for someone new to Unity.

> **Read this first: generated content gets overwritten.**
> Running **Exit Clause > Build Everything**, **4. Build Prefabs** or **5. Build All Scenes** regenerates the prefabs (`Assets/_Game/Prefabs`), materials and scenes from code. Anything you drag into those files by hand is lost on the next rebuild. Two safe ways to work:
> 1. Put all your imported art in **`Assets/ThirdParty/<PackName>/`** (never inside `_Game/`), and
> 2. Either stop running the generators once you start dressing a scene by hand, **or** add your changes to the generator scripts (`Assets/Editor/PrefabBuilder.cs`, `Assets/Editor/Scenes/Build*.cs`) so they survive a rebuild.
>
> Before any big swap, commit your work in git, so you can undo it.

**Licences:** everything below is free to use in commercial and portfolio projects (Mixamo: Adobe terms; Poly Haven and Kenney: CC0; Unity Asset Store: Standard EULA; Quixel/Fab: Fab's free licence). Keep a `Assets/ThirdParty/CREDITS.txt` that lists what you used and where it came from.

## 1. Mixamo characters and animations

Mixamo ([mixamo.com](https://www.mixamo.com)) has free rigged humanoid characters and thousands of animations. You need a free Adobe account.

### 1a. Download a character

1. Go to mixamo.com and sign in.
2. Click the **Characters** tab and pick one (for example a suited man for Kade, or a soldier for agency agents).
3. Click **Download**. Set **Format: FBX for Unity (.fbx)** and **Pose: T-pose**, then click **Download**.

### 1b. Download animations (with the same character selected)

Click the **Animations** tab, search for each animation below, and download it with **Format: FBX for Unity**, **Skin: Without Skin**, **Frames per second: 30**. For the movement loops (idle, walk, run, crouch walk), tick **In Place** before you download.

| Animator state | Mixamo search |
|---|---|
| Idle | "Idle" or "Rifle Idle" |
| Walk | "Walking" |
| Run | "Running" |
| Crouch idle / Crouch walk | "Crouch Idle", "Crouch Walk" |
| Aim | "Pistol Idle" or "Rifle Aiming Idle" |
| Cover | "Cover Idle" or "Crouch To Stand" (lean against a wall) |
| Fall / jump | "Falling Idle" |

### 1c. Import into Unity

1. In the **Project** window, right-click `Assets` > **Create > Folder**, and name it `ThirdParty`. Inside it, create `Mixamo`.
2. Drag the downloaded `.fbx` files from Explorer into `Assets/ThirdParty/Mixamo`.
3. Click the **character** FBX. In the **Inspector**, open the **Rig** tab, set **Animation Type: Humanoid**, set **Avatar Definition: Create From This Model**, and click **Apply**.
4. Click the **Materials** tab and click **Extract Textures...**, then **Extract Materials...** (choose the same folder). If the materials look pink, select them and use **Edit > Rendering > Materials > Convert Selected Built-in Materials to HDRP**. If that menu is missing, set each material's shader to **HDRP/Lit** by hand and reassign the textures.
5. Select **all the animation FBXs**. In the **Rig** tab, set **Animation Type: Humanoid**, set **Avatar Definition: Copy From Other Avatar**, and set **Source** to the character's avatar (it ends in `Avatar`). Click **Apply**.
6. For each looping animation, click it, open the **Animation** tab, tick **Loop Time** (and **Loop Pose**), and click **Apply**.

### 1d. Build the Animator Controller

`CharacterAnimatorBridge` (`Assets/_Game/Scripts/Player/CharacterAnimatorBridge.cs`) already sends these parameters every frame. **The names must match exactly** (they are case-sensitive):

| Parameter | Type | Meaning |
|---|---|---|
| `Speed` | Float | Horizontal speed in m/s (0 = still, about 2 = walk, about 5 or more = run) |
| `Crouch` | Bool | The player is crouching |
| `Aim` | Bool | The player is aiming a weapon |
| `Cover` | Bool | The player is in cover |
| `Grounded` | Bool | The player is on the ground |

1. Right-click `Assets/ThirdParty/Mixamo` > **Create > Animator Controller** (in Unity 6: **Create > Animation > Animator Controller**), and name it `Kade.controller`.
2. Double-click it to open the **Animator** window.
3. In the **Parameters** tab (top left), click **+** and add the five parameters from the table with exactly those names and types.
4. Right-click the empty grid > **Create State > From New Blend Tree**, and name it `Locomotion`. It becomes the default (orange) state.
5. Double-click `Locomotion`. Set **Parameter** to `Speed`. Click **+ > Add Motion Field** three times and drag in Idle (threshold 0), Walk (2) and Run (5.5). Untick **Automate Thresholds** if you need to type them in.
6. Click **Base Layer** at the top to go back. Make a second blend tree `CrouchLocomotion` (Crouch Idle at 0, Crouch Walk at 2).
7. Right-click `Locomotion` > **Make Transition** to `CrouchLocomotion`. Click the arrow, untick **Has Exit Time**, and add the condition `Crouch` `true`. Make the transition back with `Crouch` `false`.
8. Add an `Aim` state and a `Cover` state the same way (conditions `Aim` true/false and `Cover` true/false), and an `Airborne` state (Falling Idle) for `Grounded` false.
9. Optional but nicer: add a second layer `UpperBody` with an **Avatar Mask** for the arms only, so aiming plays while you walk.

### 1e. Put the character on the Player

1. Open `Assets/_Game/Prefabs/Player.prefab` (double-click it).
2. Drag the Mixamo character FBX onto the `Player` root in the Hierarchy, so it becomes a child. Set its **Position** to `0,0,0`, set **Rotation** to `0,0,0`, and check that the feet touch the ground (the CharacterController is 1.8 m tall, centred at y 0.9).
3. On the character child, find the **Animator** component, set **Controller** to `Kade.controller`, and **untick Apply Root Motion** (the `PlayerMotor` code moves the player, not the animation).
4. Select the `Player` root. In **Character Animator Bridge**, drag the character child into the **Animator** slot. If you leave it empty, the bridge finds the first Animator in the children on its own.
5. Hide the greybox: tick off the `Body` child (the capsule humanoid). **Better:** drag your character into the **Player Character > Body Visual** field instead. The game hides `bodyVisual` when you hide in a closet or ride in a car, so it needs to point at the visible model.
6. Move the `Muzzle` child to the gun hand if your character holds a gun. Otherwise leave it where it is.
7. Press **Play** in any scene. Walk, crouch (C) and aim, and watch the parameters change in the Animator window.

Agents (`Agent.prefab`) and civilians (`Civilian.prefab`) use the same steps with their own characters. The enemy AI does not drive an animator yet, so add a small script, or simply reuse the bridge idea, when you get there.

> Remember: **4. Build Prefabs** regenerates `Player.prefab` and removes your character. Either stop running that step, or make a **Prefab Variant** and ask for `PrefabBuilder` and the scene builders to use the variant.

## 2. Poly Haven: HDRIs, textures and models (CC0)

[polyhaven.com](https://polyhaven.com) has free HDRI skies, PBR textures and props.

### 2a. HDRI sky

1. Go to **HDRIs**. Pick one that fits the scene: a sunny coast for the Riviera, an overcast city for Prague or Berlin, snow for the Alps, a dusk harbour for the Interlude.
2. Download **2K or 4K** in **EXR** format (HDR also works).
3. Drag it into `Assets/ThirdParty/PolyHaven/HDRI`.
4. Click it. In the Inspector, set **Texture Shape: Cube** and **Mapping: Latitude-Longitude Layout (Cylindrical)**, then click **Apply**.
5. Open the scene. In the Hierarchy, select **Global Volume**. Its profile is saved in `Assets/_Game/Settings/Volumes/<Mood>.asset`.
6. In the profile, open **Visual Environment** and set **Sky type: HDRI Sky**.
7. Click **Add Override > Sky > HDRI Sky**. Drag your cubemap into **HDRI Sky**, then tune **Exposure** and **Rotation** so the sun lines up with the scene's directional light.
8. Note: **LightingBuilder** rebuilds the volume when scenes are regenerated. Make a copy of the profile and assign the copy if you want your change to stay.

### 2b. Textures (materials)

1. Go to **Textures** and download at **2K** as **PNG** or **JPG**: the *Diffuse*, *Normal (GL)*, *Roughness*, *AO* (and *Displacement* if you want).
2. Import them into `Assets/ThirdParty/PolyHaven/Textures/<Name>`. Click the normal map and set **Texture Type: Normal map**.
3. HDRP/Lit uses a **Mask Map** (R = metallic, G = AO, A = smoothness). The quick way: create a material (**Create > Material**, shader **HDRP/Lit**), put the diffuse in **Base Map** and the normal in **Normal Map**, and set **Metallic** and **Smoothness** with the sliders.
4. To swap a greybox material, select a wall and drag your new material onto it in the Scene view. Or replace a whole family: the greybox material names (`Brick`, `Cobblestone`, `Marble`, `Plaster`, `Asphalt`, and so on, in `Assets/_Game/Materials`) are created by `MaterialLibrary`, so you can update the textures there to change every scene at once (the generator may overwrite them; see the warning at the top).

### 2c. Models

Poly Haven **Models** (furniture, props) come as FBX or glTF. Use **FBX** for easy import. Drag one in and convert its materials to HDRP/Lit as in step 1c.4.

## 3. Unity Asset Store: free HDRP-compatible packs

1. In Unity: **Window > Package Manager**, or open [assetstore.unity.com](https://assetstore.unity.com) in a browser.
2. On the site, filter **Pricing: Free** and search for **"HDRP"**. Check the **Render pipeline compatibility** box on the product page: it must list **HDRP**. Built-in-only packs will turn pink.
3. Click **Add to My Assets**.
4. In Unity: **Window > Package Manager** > the dropdown at top left: **My Assets** > find the pack > **Download** > **Import**. In the import dialog, untick demo scenes you do not need, then click **Import**.
5. Move the imported folder under `Assets/ThirdParty/` (drag it in the Project window).
6. If something is pink, use **Edit > Rendering > Materials > Convert ...** or set the shader to HDRP/Lit.

Worth a look (all free, but check the current HDRP support):
- **Unity's HDRP sample content**: in Package Manager, go to *High Definition RP* > *Samples* and import the material samples.
- **Starter Assets: Third Person** (Unity). Useful *only* for its animations and controller as a reference. Do not replace `PlayerMotor`.
- Free "city", "street props" or "European buildings" packs that are HDRP-tagged, for Prague, Marseille and Zurich.
- Free car packs for `Car.prefab`. Keep the generated wheel setup; only swap the visuals (the `CarController` `wheelVisuals` field).

## 4. Kenney (CC0)

[kenney.nl/assets](https://kenney.nl/assets) has simple, consistent low-poly props, UI packs, sounds and fonts.

1. Download a pack (for example *City Kit*, *Car Kit*, *Furniture Kit*, *UI Pack*, *Interface Sounds*, *Impact Sounds*). It arrives as a `.zip`.
2. Unzip it. Drag the `Models/FBX format` folder into `Assets/ThirdParty/Kenney/<Pack>`.
3. Kenney models share one colour-palette texture. Make an HDRP/Lit material that uses it and assign it to the models.
4. **Sounds:** drag `.ogg` files into `Assets/_Game/Audio` or `ThirdParty/Kenney/Audio`. `AudioService` plays clips you assign, for example `SceneMissionDirector.music` for scene music.
5. **UI:** the UI is generated in code by `UIKit`, which uses the built-in font. To use a Kenney font, import the `.ttf` and change `UIKit.Font` (code change).

## 5. Quixel Megascans (free on Fab)

Quixel's photoscanned surfaces, 3D assets and plants now live on **Fab** ([fab.com](https://www.fab.com)). Many Megascans are free.

1. Sign in to fab.com with an Epic account. Filter **Price: Free** and look under **Megascans**.
2. On an asset, click **Download** and pick the **Unity** format if it is offered. Otherwise pick **FBX** plus textures at **2K**.
3. Import into `Assets/ThirdParty/Quixel/<Asset>`.
4. Create an **HDRP/Lit** material:
   - **Base Map**: the *Albedo* texture.
   - **Normal Map**: the *Normal* texture (set its Texture Type to *Normal map*).
   - **Mask Map**: Megascans often ships an ORM or separate AO/Roughness. If there is no ready-made mask, use the Metallic and Smoothness sliders, or build a mask map in an image editor (R = metallic, G = AO, B = detail mask, A = smoothness, which is *1 - roughness*).
5. Rocks and cliffs suit `Act2_Alps`, and surfaces suit `Act0_Riviera` and `Act1_Mansion`.

## Quick checklist after any import

- [ ] The assets live under `Assets/ThirdParty/...`, not inside `_Game/`
- [ ] No pink materials (they are all HDRP/Lit or another HDRP shader)
- [ ] Characters: Rig = Humanoid, Apply Root Motion is **off**, the Animator parameters match `Speed`/`Crouch`/`Aim`/`Cover`/`Grounded`
- [ ] Colliders: imported meshes have **no** collider by default. Keep the greybox colliders, or add **Mesh Collider** / **Box Collider** components. NavMesh: rebake if you changed walkable geometry (`RuntimeNavMeshBaker` or the generated `*_NavMesh.asset`)
- [ ] `CREDITS.txt` is updated
- [ ] Committed in git before you run any `Exit Clause > Build ...` menu item again
